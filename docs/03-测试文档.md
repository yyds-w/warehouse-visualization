# 简简仓库可视化系统 — 测试文档

## 1. 测试范围

本文档覆盖以下模块的测试：

- 仓库信息管理（CRUD）
- 子仓库管理
- 库管信息管理
- 平面图绘制与导入
- 货架配置
- 货位管理
- 智能找货
- 全景可视化看板

## 2. 测试方法

| 测试类型 | 方法 | 工具/手段 |
|----------|------|-----------|
| 单元测试 | 对后端 Service、工具类（如货位编码生成、坐标计算）进行方法级测试 | JUnit / PyTest |
| 接口测试 | 对 CRUD 及查询接口进行请求/响应断言，覆盖正常与异常参数 | Postman / Apifox |
| 功能测试 | 按验收点手工执行界面操作，验证功能正确性 | 手工 + 浏览器 |
| 联动测试 | 验证跨模块数据联动（如货架配置变更后看板数据刷新） | 手工 |
| 边界测试 | 对输入边界（尺寸为 0、超大参数、特殊字符）进行验证 | 手工 + 接口脚本 |
| 性能测试 | 验证找货响应时间、看板加载时间 | JMeter / 前端 Performance 面板 |
| 兼容性测试 | 验证主流浏览器（Chrome、Edge、Firefox）下的平面图渲染 | 手工 |
| 回归测试 | 每轮缺陷修复后，重跑核心用例，防止功能回退 | 用例集 |

## 3. 测试环境

- 操作系统：Windows 11
- 浏览器：Chrome（主）、Edge、Firefox
- 后端：本地开发环境，数据库使用测试库（独立于生产数据）
- 测试数据：预置 1 个仓库、2 个子仓库、3 个货架（每货架 1行2排3列4层=24 货位）、2 名库管、10 个 SKU 的库存数据

## 6. 缺陷管理

- **严重级别**：
  - P0（致命）：数据丢失、系统崩溃、核心功能不可用
  - P1（严重）：主流程受阻、计算结果错误
  - P2（一般）：非主流程功能异常、交互瑕疵
  - P3（轻微）：文案、样式问题
- **回归策略**：P0/P1 修复后必须回归全部核心用例；P2/P3 修复后回归关联用例。
- **准入/准出**：
  - 准入：提测需通过冒烟测试（WH-001、SF-001、SR-001 通过）
  - 准出：P0/P1 缺陷清零，P2 缺陷遗留率 ≤ 10%，核心用例通过率 100%
