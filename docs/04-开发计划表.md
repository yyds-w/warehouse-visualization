## 〇、概览

### 技术栈（已确认）

- **后端**：SpringBoot 3.2.5 + MyBatis + H2 内嵌数据库 + Lombok + Validation
- **前端**：Vue 3.5 + Vite 5 + Element Plus 2.8 + Axios
- **沿用原型**：`此前的汽车营销系统项目`（五层结构 + 统一 `Result`/`PageResult` 返回 + Vue3 页面风格）

### 关键决策

| 项 | 决策 | 理由 |
|---|---|---|
| 数据库 | **H2 文件模式**（`MODE=MySQL`） | 本机未装 MySQL；SQL 用 MySQL 方言写，日后换真库只改 `application.yml` 三行 |
| 分页 | **手写 `LIMIT #{offset},#{pageSize}`** | 不引 PageHelper，少一个依赖、行为可控 |
| 删除 | **逻辑删除**（`deleted=0/1`） | 仓库是主数据，物理删除会破坏历史单据外键 |
| 鉴权 | **本期不做** | 最利于冒烟验证，见「待确认项」 |
| 端口 | 后端 **8081**、前端 **5174** | 避开 `汽车营销系统` 占用的 8080 / 5173 |

### 待确认项（执行中如无异议按默认走）

1. **登录鉴权**：本期默认不做，所有接口匿名可访问。若需做，另加步骤（Login + JWT 拦截器）。
2. **仓库类型枚举**：默认 `原料仓/半成品仓/成品仓/冷链仓/危险品仓/暂存仓`，可增删改。
3. **建筑面积单位**：默认平方米（㎡），保留 2 位小数。
4. **多租户/数据权限**：本期单租户，不做。

## 二、仓库表字段定义（步骤 5–11 的共同基线）

表名 `warehouse`

| 字段 | 类型 | 必填 | 含义 | 校验规则 |
|---|---|---|---|---|
| `id` | BIGINT PK AUTO_INCREMENT | — | 主键 | 自增 |
| `warehouse_code` | VARCHAR(32) | ✅ | 仓库编号 | **唯一**；4–32 位；仅字母/数字/`-`/`_`/大写 |
| `warehouse_name` | VARCHAR(64) | ✅ | 仓库名称 | 2–64 字符；同一区域内不可重名 |
| `warehouse_type` | VARCHAR(20) | ✅ | 仓库类型 | 枚举：原料仓/半成品仓/成品仓/冷链仓/危险品仓/暂存仓 |
| `region` | VARCHAR(64) | ❌ | 所属区域/地址 | ≤64 字符 |
| `building_area` | DECIMAL(10,2) | ❌ | 建筑面积(㎡) | >0 且 ≤999999.99 |
| `manager_name` | VARCHAR(32) | ❌ | 库管负责人 | ≤32 字符 |
| `manager_phone` | VARCHAR(20) | ❌ | 联系电话 | 正则 `^(\d{3,4}-?\d{7,8}|1[3-9]\d{9})$` |
| `status` | TINYINT | ✅ | 启用状态 | 1=启用 0=停用；默认 1 |
| `start_date` | DATE | ❌ | 启用日期 | 不得晚于今天 |
| `remark` | VARCHAR(255) | ❌ | 备注 | ≤255 字符 |
| `create_time` | DATETIME | — | 创建时间 | 插入时自动填充 |
| `update_time` | DATETIME | — | 更新时间 | 插入/更新时自动填充 |
| `deleted` | TINYINT | — | 逻辑删除 | 0=未删 1=已删；默认 0 |

> **H2 注意**：所有字段名在 SQL 中用反引号包裹（MySQL 与 H2 `MODE=MySQL` 均支持），避免 `status`/`type` 之类潜在关键字冲突。

#### 步骤 8：Entity 与公共类

- **目标**：数据载体 + 统一返回 + 全局异常处理就位
- **产出物**：
  - `entity\Warehouse.java`
  - `common\Result.java`、`common\PageResult.java`、`common\ResultCode.java`
  - `common\BusinessException.java`、`common\GlobalExceptionHandler.java`
- **前置依赖**：步骤 7
- **执行要点**：
  - `Warehouse` 用 Lombok `@Data`，加 Jakarta Validation 注解：`@NotBlank` 编号/名称、`@Pattern` 编号与电话、`@Size` 名称、`@DecimalMin/@DecimalMax` 面积、`@NotNull` 状态
  - `Result`/`PageResult`/`ResultCode` 直接照搬参考项目的实现（结构：`code/message/success/data/timestamp`；分页：`list/total/pageNum/pageSize/pages`）
  - `GlobalExceptionHandler` 用 `@RestControllerAdvice` 处理三类：
    - `MethodArgumentNotValidException` → 400 + **拼接首个字段错误中文提示**
    - `BusinessException` → 400 + 自定义消息
    - `Exception` → 500 + "服务器内部错误"
- **验收标准**：
  - 代码编译通过（`mvn -q compile`）
  - 注解与字段基线一一对应，无遗漏

---

#### 步骤 9：Mapper 层（动态条件查询 + 分页）

- **目标**：数据访问层，支持模糊查询、多条件筛选、分页、逻辑删除过滤
- **产出物**：
  - `mapper\WarehouseMapper.java`
  - `resources\mapper\WarehouseMapper.xml`
- **前置依赖**：步骤 8
- **执行要点**：
  - 接口方法：`selectPage(...)`、`countByCondition(...)`、`selectById(...)`、`selectByCode(...)`、`insert(...)`、`update(...)`、`logicDelete(...)`
  - XML 用 `<sql id="Base_Column_List">` 复用列，`<where>` + `<if>` 动态条件：
    - `keyword` → 对 `warehouse_code` 和 `warehouse_name` 做 `LIKE CONCAT('%', #{keyword}, '%')`
    - `warehouseType`、`status` → 等值匹配
    - 固定追加 `AND deleted = 0`
  - 分页：`LIMIT #{offset}, #{pageSize}`（`offset` 由 Service 算 `(pageNum-1)*pageSize`）
  - `insert` 用 `useGeneratedKeys="true" keyProperty="id"`
- **验收标准**：
  - 编译通过；XML 无 MyBatis 解析错误
  - 启动时 MyBatis 日志打印出 Mapper 已注册

---

#### 步骤 10：Service 层（业务校验）

- **目标**：把业务规则收口在 Service，Controller 只做转发
- **产出物**：
  - `service\WarehouseService.java`
  - `service\impl\WarehouseServiceImpl.java`
- **前置依赖**：步骤 9
- **执行要点**：
  - `page(query)`：默认 `pageNum=1, pageSize=10`，上限 `pageSize≤100`；查列表 + 查总数 → 组装 `PageResult`
  - `getById(id)`：查不到抛 `BusinessException("仓库不存在")`
  - `create(dto)`：**先校验 `warehouse_code` 唯一**（`selectByCode` 有记录 → 抛"仓库编号已存在"）；再 insert
  - `update(dto)`：`id` 为空抛异常；先查存在性；**若改了编号，需排除自身后判重**
  - `delete(id)`：先查存在性；再 `logicDelete`（把 `deleted` 置 1）
  - 所有写操作由 XML 负责填充 `create_time`/`update_time`
- **验收标准**：
  - 编译通过

#### 步骤 11：Controller 层（5 个 REST 接口）

- **目标**：对外暴露完整 CRUD 接口
- **产出物**：`controller\WarehouseController.java`
- **前置依赖**：步骤 10
- **执行要点**：`@RestController @RequestMapping("/api/warehouse")` `@Validated`，5 个方法：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/warehouse/page` | 分页查询，入参 `keyword/warehouseType/status/pageNum/pageSize` → `Result<PageResult<Warehouse>>` |
| GET | `/api/warehouse/{id}` | 详情 → `Result<Warehouse>`，不存在抛业务异常 |
| POST | `/api/warehouse` | 新增，`@RequestBody @Valid Warehouse` → `Result<Warehouse>`，message="新增成功" |
| PUT | `/api/warehouse` | 编辑，`@RequestBody @Valid Warehouse`，id 必填 → `Result<Void>`，message="修改成功" |
| DELETE | `/api/warehouse/{id}` | 逻辑删除 → `Result<Void>`，message="删除成功" |

另加 `WebMvcConfigurer` 允许跨域（`allowedOriginPatterns("*")`，便于必要时前后端分离直连）。

- **验收标准**：

#### 步骤 16：后端接口冒烟（curl 全量实测）

  3. `GET /api/warehouse/page?status=0` → 200，仅停用仓

  7. `POST /api/warehouse` **电话格式错** → 400

## 四、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Maven 首次拉依赖慢/超时 | 步骤 2 卡住 | 后台执行 + 必要的国内镜像（`settings.xml` 配阿里云） |

| Lombok 与 JDK17 注解处理 | 编译失败 | pom 中显式配置 `maven-compiler-plugin` 的 annotationProcessorPaths（照搬参考项目） |
